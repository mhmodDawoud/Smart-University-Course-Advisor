# Project plan

Delivery and discussion dates are announced later by the instructor; update this file when known.

## Phases

1. **Design**: agree on the data schema, the interfaces between components and the algorithm choices.
2. **Data**: collect or generate data, clean it, document it.
3. **Components** (in parallel): Searching, Learning, Optimization.
4. **Integration**: connect the three components end to end.
5. **Evaluation**: baselines, metrics, comparison, conclusions.
6. **App and demo**: user interface for discussion day.
7. **Report and presentation**.

Tip: integrate early. Do not leave the connection between components until the last week.

## Suggested module slots (10 people)

Assign names in the README members table. Pairs help everyone understand more than one part.

| Slot | Responsibility |
|---|---|
| 1 | Course catalog and prerequisites data |
| 2 | Timetable / sections data |
| 3 | Student performance data and preprocessing |
| 4 | Learning model: training |
| 5 | Learning model: features and evaluation |
| 6 | Search: implementation |
| 7 | Search: constraints and tests |
| 8 | Optimization: implementation |
| 9 | Evaluation, baselines and experiments |
| 10 | App / demo |

Report and presentation are shared: everyone writes the part they built.

## Individual discussion reminder

Part of the grade is individual: each member must understand the whole pipeline and be able to explain
their own contribution. Rotate review duties so everyone reads code outside their own module.
